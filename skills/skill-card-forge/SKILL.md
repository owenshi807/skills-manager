# Skill Card Forge

Turn a stable work scene and its grounded source material into an original equipment card. The card's primary unit is one identifiable scene, not one Skill: read [scene card v1](references/scene-card.md) before creating, evolving, comparing, or reviewing a card. A scene can draw on many Skills, and the same Skill can support many scenes. Do not batch-produce a separate card for every underlying Skill.

Grade and art style are independent axes: preserve the evidence-backed scene review result; never infer or change it from how impressive the image looks. Start with a complete static artwork. A user can request one card; never require all grades.

For scene-card naming, value sentences, front/back copy, ability explanations, copy generation prompts, JSON contracts, or copy review, read [card copy v0.1](references/card-copy.md) after the scene-card contract. It remains the reusable standard for grounded underlying-Skill summaries, not an instruction to turn every summary into a card. Copy-only requests do not require artwork or a grade record. Ground claims in the complete source and verified dependency scope; retain honest source excerpts or missing-copy states when evidence is insufficient. Never derive grade, automation, or personal ability from copy. Existing grade records remain governed by the art and evolution contract.

Read [art and evolution](references/art-and-evolution.md) for any art request. For an image-generation request, use the installed **system `imagegen` Skill with the built-in `image_gen` tool** when available; it needs no API key. If it is unavailable, provide a ready-to-run prompt and say no image was generated. Do not select a legacy same-named paid API/CLI.

For card artwork, read installed `holo-card-studio` and its `references/art-direction.md` to keep composition and eventual layers compatible with the original card-making workflow. Static style comparisons do not need to run Blender; generation and full 3D export are distinct deliverables.

For layered, motion, or 3D delivery, also read [production and 3D adaptation](references/production-and-3d.md). Use installed `holo-card-studio` only for a requested full 3D export; state any missing capability and continue in prompt/static mode rather than silently substituting or rewriting its engine.

Deliver the artwork or prompt, identify one established feature, and offer at most one next inspiration. Do not claim a static or layered image is a volumetric object, interactive export, or animation.
