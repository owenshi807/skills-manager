# 卡牌大师：Skill 评级与永久突破成就 v1

日期：2026-09-09。状态：产品基础规则；取代 [v0](skill-rating-foundation-v0.md) 的等级、个人化、失效与皮肤规则。**本轮完成规范与案例校准，尚未实现评级、发放真实奖章或修改生产卡面。**

## 1. 已确定的产品对象

**卡牌记录 Skill 拥有什么方法、实现过什么突破；持有这张卡不证明持有人具备同等能力。**

当前建设 Skill Card 库。未来 Profile 库独立建立人的能力证据；当前不创建该库，不采集个人成长数据，不从持卡、调用、收藏或修改次数推导个人能力。用户选择的是两个库的分离，而非在 Skill 卡上继续追加人物悟道等级。

| 对象 | 回答的问题 | 规则 |
|---|---|---|
| Skill Card | 库里拥有哪种可调用的方法？ | 可来自原创、改造、组合或导入；来源和归属可追溯 |
| 当前场景评估 | 这个版本在这个任务中，已证明能做什么？ | 随版本、场景与运行环境重新验证 |
| Skill 突破成就 | 这个 Skill 曾经跨过什么方法门槛？ | 一次成立的突破即可永久解锁 SSR |
| 未来 Profile 库 | 这个人自己已经掌握什么？ | 独立对象、独立证据；本轮仅保留此边界 |

“适配了 Owen 的偏好”仍是 Skill 版本的来源与适用条件，不是 Owen 的能力分。通用 Skill 可以很强，个人适配版也可以尚未验证。

## 2. 三个常规等级，一个隐藏成就

常规卡采用 **C → R → SR**；不另加 U、S。SSR 隐藏，解锁后永久保留。SSSR 仅是讨论未来边界的参照，当前没有枚举、待解锁槽、阈值或皮肤承诺。

| 卡面 | 简称 | 方法上发生了什么 | 不能凭什么升级 |
|---|---|---|---|
| C | 基础 | Skill 已进入库，尚无充分证据证明达到更高层；同时容纳普通方法与待验证方法 | C 不代表测过、不代表低于市场，也不代表所有 C 都已可用 |
| R | 成法 | 将任务组织为可复用方法，关键要求不靠碰巧记起，交付具有可检查的价值 | 有文件、步骤多、格式漂亮、单次模型答对 |
| SR | 通理 | 在相关情境中判断何时用哪条方法，区分好坏、处理冲突、识别边界并知道何时停止 | 更长、更抽象、框架更多、更多工具或更高调用量 |
| SSR（隐藏） | 突破成就 | 一次实质方法突破已进入 Skill，并有实例显示新增的判断原则改变了结果或行动 | 幸运输出、漂亮口号、自称“涌现”、仅把原有方法补完整 |

R/SR 是当前范围内的方法能力判断；SSR 是已经发生的突破成就。卡面可以用更稀有的视觉呈现 SSR，但数据与文案不能把它解释为“现在所有任务都比 SR 强”。这正是永久解锁与诚实评价能够共存的基础。

“初识、成法、通理、悟新理”可以辅助理解梯度，但主语始终是 Skill。修仙隐喻不进入个人 Profile，也不成为通用心理成长量表。

## 3. SSR：一次突破，永久解锁

一次突破要能回答三个问题。这是审阅所需的证据，不要求每次调用填写三张表。

1. **突破了什么？** 旧方法在哪种重要情境下失灵？新增了什么有效区分、问题框架或行动原则？新方法为何改变了原有能力边界？
2. **落在哪里？** 变化已经进入可复用的 Skill 指令、方法、工具分工或明确的组合。只存在于一段聊天中的精彩回答，应先保存为候选成果。
3. **看到了什么差别？** 至少一个真实实例或有针对性的对照，能指明判断、行动或交付变化及其原因；同时说清该原则的适用边界，不把一次成功写成普遍规律。

三个问题共同成立，即可认可这一次 Skill 突破。**不要求第二次突破，不要求先刷满 SR 样本数，不要求使用者学会，也不要求全行业原创。**样本不足以证明广泛稳定性时，当前适用性仍如实标注，但不因此否认已经证实的突破。

2026-09-09 用户补充：审核 AI 以帮助方法成长、鼓励用户达到圣品为导向，依据已有材料给出结论。先说明已经成立的价值；证据不足时给一个可操作的小改进或对照建议，材料足够则不追加作业。鼓励不靠编造证据或提高门槛；绘图丰富度、生灵数量、3D 与动画都不参与能力评级。合法圣品后，用户可持续重绘器物与领域；纯视觉变化不重审突破、不重复授奖，也不新增 SSR+ 等等级。

突破必须具有实质性：修正一个算术错误、增加一个既有 checklist、补齐文档，通常属于修复或 R 的完善；能按已知条件选用已有方法，是 SR 的典型表现；重新辨认问题结构，生成原方法没有的有效区分并改变工作法，才是 SSR 的典型表现。不能故意选一个空白或残缺基线，把正常专业做法包装成突破。

新颖性以明确的旧方法、相关已知方法和问题范围为参照；“首次写进这份文件”不等于方法突破。“行业领先”需要额外外部对照，SSR 不自动包含这个承诺。

### 获得方式与归属

- 原创或改造：把有效突破沉淀进 Skill，保留变化与实例。
- 导入或分享：可继承有可核验来历的 SSR 卡及其成就记录；持有人获得卡，不因此获得作者身份或个人能力证明。只有一个 `SSR` 标签、作者名气或同名文件不能继承有效成就。
- 组合：突破属于组合时，先归属于该组合卡及其组成版本；不自动给每个成员补发 SSR。只有能指明某成员实际承载的方法变化，才单独判断它的资格。

这些是允许的取得路径，不是本轮已实现的交易、签名认证或自动授奖系统。首批真实发牌仍需把实例与确切 Skill 身份绑定并记录判断依据。

### 永久与当前状态

合法授予的 SSR 永久保留。Skill 更新、模型变化、依赖损坏、评测过期或后来出现更强方法，都不能以 `stale` 为由收回已获得的成就或皮肤资格。

与此同时，当前版本可以是“本场景待验证”“当前环境不可用”或“发现问题，待修复”。这些状态影响调用建议，不删除历史突破。历史成就保留其版本、范围与证据，不能被新版本冒充。

错误归属或伪造证据属于记录纠错，不属于正常能力降级：保留纠错历史，不能把未经核验的声称视为合法授奖。具体导入核验和纠错交互留给实施阶段，不新建常驻审核系统。

## 4. 用审美定义等级，用评测检验承诺

《高手的黑箱》给出的启发是：能比照、指出具体落差、进行改进，并知道何时结束。高阶建模进一步要求把决定性关系压缩成模型，再展开为现实可用的方法。**等级的差异在于新增了什么判断；评测的作用是检查这项判断是否有证据。**这些等级是本产品的推论，不是课程作者制定的认证。

| 检验层 | 实际怎么判 | 作用 |
|---|---|---|
| 基本质量 | 证据正确、任务覆盖、判断成立、交付可用；关键错误单列 | 防止华丽但错误的产物取得高评价 |
| R 的成法 | 同一场景的代表任务与边界任务，在相同运行条件下比较基线与 Skill；检查可复用的收益及失败 | 区分方法价值与模型本来就会的能力 |
| SR 的通理 | 设置表面相似但关键条件不同的对照；要求选择、取舍、证据冲突处理与适时停止；加入独立评审 | 区分照搬模板与真正的条件判断 |
| SSR 的突破 | 重开旧方法、具体变更、对照实例及边界；解释新原则实际造成的差别 | 确认一次方法突破已经发生 |
| 行业内的位置 | 对指定同任务、同条件的外部参考方案做可追溯对照，披露检索范围与日期 | 只能得出该参照范围的结果，不推出全球排名 |

沿用 v0 的 E/C/J/D 四维诊断锚点与严重错误规则，但 **20/40/80 题、80/85/90% 等旧晋级数字停止作为等级定义**。它们只是历史采样方案，未经校准，不得换个名字继续作为隐藏门槛。C 基础入口无需先通过二十题。

正式 R/SR 评估应在运行前冻结场景任务画像、代表任务与反例、成功断言、关键失败、对照、样本及重复设计、判定规则。样本规模与不确定性按承诺强度设定；本规范未给所有场景强行规定一个数字。未完成该场景协议的校准，不能自动算出 R/SR。

任务数与重复调用次数分开报告；模型、工具、预算、依赖与证据来源保持可比较；盲审与确定性检查各用于适合的部分。保留失败、成本与耗时，不靠平均分掩盖致命错误。SSR 的单次突破审阅不要求运行一整套广泛能力 benchmark。

现有 [12 道市场研究公开开发题](benchmarks/skill-rating-v0/README.md)继续用于校准基本质量；公开答案不是 holdout，没有真实 Skill 测评结果。本轮没有给 `market-scale`、`business-coach` 或 `demand-insight` 发牌；它们在 v1 中是 **C · 待验证**，不是已测低分。

## 5. 最小记录与两库边界

以下是未来接入所需的概念合同，不是本轮新增的数据库或 metadata 实现。

| 记录 | 最少需要保留什么 |
|---|---|
| Skill 身份 | 稳定身份、确切内容与依赖版本、来源、派生或组合关系；不能以名称代替身份 |
| 场景评估 | Skill 版本、场景/任务范围、模型工具预算、协议与证据、日期、当前 R/SR 或证据不足/失败原因 |
| 突破成就 | 归属 Skill 或组合、获奖版本、突破前后原则、对照实例、成立边界、审阅依据与日期 |
| 入库来源 | 原创/改造/导入/组合的来历；已有奖章的原始归属和证据链 |

Scene 仍然表达任务上下文，不能从一张 SSR 推导整个场景或全库都是 SSR。普通场景能力按当前证据显示；SSR 成就可随卡展示，但需能看见“突破于什么场景”。

当前评级变更不会覆盖成就记录。内容变化使当前评估待复验，不使成就消失。同名替换、不同分支、未知来源导入不能仅靠名称挪用他人的成就。未来 Profile 可以引用持卡事实作上下文，但不能把它当个人能力证据。

## 6. holo-card 皮肤合同

已安装 RedSkill `holo-card@1.0.1`，声明名为 `holo-card-studio`。评级基础首次编写时未生成卡面，后续已有独立器物与交互原型。以下视觉权限按用户 2026-09-09 的后续决定同步；具体绘图以 [凡灵天圣绘图内核 v1](skill-cultivation-visual-foundation-v1.md) 为准，评级和永久成就规则不变。

| 卡面 | 视觉资格 | 当前状态怎么表达 |
|---|---|---|
| C／凡 | 普通印刷、精致基础器物、静态光影；无镭射、金箔或稀有粒子 | 以小字区分待验证、已检查基础、待改进；不新增 U 卡种 |
| R／灵 | 新增可复用的器内结构、普通材质反射与分层视差；无镭射、发光刻线或稀有金框 | 展示已验证的任务范围 |
| SR／天 | 有条件关系的独立器物形态、装备局部镭射、细金边、环境视差；无静止时的时间循环 | 展示能处理的关键情境与边界 |
| SSR／圣（已解锁） | 独有结构与领域、全卡全息（避开文字）、永久突破纹章；允许可暂停的器内与领域慢运动 | 永久保留成就皮肤；另显当前场景/版本状态与突破出处 |

这四种卡面不是强制四级晋升路径。SSR 成就先成立，美术按其资格制作；画作尚未完成或未达到视觉验收，不能推迟或收回合法成就。微倾随鼠标位置变化，点击翻面；不自动整卡旋转、扫光或闪烁。

SSR 未解锁时不在普通等级表挂锁催促、不显示刷卡进度、不展示“还差 N 次调用”；发现并认可突破后才揭晓。SSR 在列表和详情的成就资格都不因当前验证过期而撤销。R/SR 若当前证据失效，可降低当前能力视觉并保留历史结果；这条规则不能套到永久 SSR 上。

普通卡不能只设置模板 `foil=0`：供应模板的边缘、背面 rainbow 和固定金材质仍需独立关闭。适配层统一控制 `frontFoil / rainbowEdge / goldMaterial / lineEmission / stars / parallax / autoMotion`，再为 SSR 提供独有纹章与揭晓状态；不修改供应商 Skill 以承载产品政策。

保持场景内容的阅读顺序，列表以静态卡面和小面积效果为主，详情只激活一张完整 3D。文字、触控/键盘与 reduced-motion 下仍能识别等级。用户关闭动画后保持 SSR 的静态纹章和金属层次。

卡面文案例：`SSR · 依赖镜头突破`，状态 `当前版本待验证`，查看成就可见旧方法、新原则与实例。没有获奖证据的样机必须显著标成演示。

## 7. 兼容与后续实施验收

v0 尚未实现生产评级，因此本轮没有数据迁移。未来首次接入时，既有未评估卡显示 C · 待验证，保留场景、组合、优先项与文件身份。已安装、已投放、归类匹配、`scoreDeckSkill()`、临时 `quality` 和 coverage 均不能代替能力评估。

最小后续顺序：先确定一张真实 Skill 的证据与绑定，制作明确标注演示的 C/R/SR/SSR 视觉对照，再接入评级与成就读取；Profile 库继续延期。不要为了发第一张卡先建设通用评测平台。

实施必须检验这些可观察结果：

1. 同一张 C 可以是待验证或基础已检查，未验证不被误读为低能力。
2. 场景、模型或版本变化只影响当前适用性；合法 SSR 与皮肤资格保留。
3. 仅一次已证实的 Skill 方法突破就能解锁，无学习测验、重复突破或调用次数要求。
4. 导入已核验成就可以持有 SSR；同名/裸标签导入不能冒领。
5. 组合奖章不会扩散给所有成员或用户 Profile；个人适配不自动升级。
6. 未解锁 SSR 不制造进度槽；C 无模板金光泄漏，关闭动画仍可识别 SSR。

真实知识库案例、哲学审计与历史证据限制见 [哲学审计与评级参照 v1](skill-rating-philosophy-audit-v1.md)。
