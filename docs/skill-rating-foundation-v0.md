# 卡牌大师：场景技能评级 foundation v0

> **历史版本，已由 [v1](skill-rating-foundation-v1.md) 取代（2026-09-09）。** v1 合并未评级与 C，采用 C/R/SR 常规卡与隐藏永久 SSR Skill 成就；Skill Card 库和未来 Profile 库分离。下文 U 卡种、个人成长轴、固定数字晋级、历史最高光效撤销及 SSR 未定义等旧规则均不再生效。四维诊断与公开开发题仍可作评测素材。

日期：2026-09-09。状态：产品规则与待校准评测合同；**尚未给真实 Skill 发放能力等级，也未实现生产评级或卡面 UI。**

## 1. 决策：三档能力，加“未评级”状态

先建立 C 普通、R 镭射、SR 金光镭射三档。对应三个足够区分的承诺：**能完成 → 稳定且有增益 → 经更强对照验证。** 未评级 U 是缺少证据的状态，不是低能力，也不是第四档。SSR/传说级不预设，只有出现现有三档无法表达的新能力与独立证据时再扩展。

一档只能区分有没有，二档混淆“可用”与“稳定有增益”，四个正式等级在没有实测分布时制造虚假精度。三档已经覆盖用户需要的三个视觉强度，并为未来保留空间。这是产品选择，不是行业公认标准。

Pokémon 官方将 common/uncommon/rare、parallel foil 和特别插画等分开说明，同一类 Pokémon 可以有不同视觉版本。我们的推论：借用它的卡面识别语言，不借用收藏稀有度作为能力证明。[官方卡面说明](https://www.pokemon.com/uk/pokemon-news/pokemon-tcg-scarlet-and-violet-revamps-pokemon-tcg-card-aesthetic)

## 2. 评级对象必须带场景和运行条件

**评级对象 = 一份确切版本的 Skill，在一个明确任务范围和固定运行条件下的表现。**

实际证据身份为 `skillId + contentHash + sceneId + taskProfileVersion + runtimeFingerprint + benchmarkVersion + policyVersion`。runtimeFingerprint 包括模型版本、Agent/harness 版本、工具权限与版本、推理/时间/Token 预算、依赖 Skill 的版本和上下文模式。模型参与结果，不能把模型升级带来的效果全归因给 Skill。

- Skill 本身：结构、触发边界、依赖、输出合同和可运行性是准入事实，不单独兑换金卡。
- 场景能力：完成实际任务的证据决定 C/R/SR。同一 Skill 在商业需求研究中为 R，在财务测算中仍可为 U；不复制最高等级。
- 个人化成长：该版本怎样适配这个用户，单独记录，不与能力分数加权相加。
- 多 Skill 组合：必须有组合版本及端到端测试才能评级；不能按最高、平均或最低成员等级推导组合等级。场景本身展示已评级覆盖，例如“8 项能力中 2 项已验证”，不取一张金卡代表整场景。

用户跨模型或跨场景查看时显示对应评级，未匹配条件显示“此环境未验证”。技能库概览只汇总各场景结果，不生成假定通用战斗力。

Anthropic 将 task、trial、grader、outcome 和 harness 分开，并强调研究任务须按任务检查来源支持、覆盖和来源质量；重复尝试与任务数不同。[Agent eval 方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

## 3. 两条轴，不设一个会掩盖问题的总分

### A. 场景能力：四维锚定评分 + 硬门槛

每次运行按四维评分，每维 0/1/2 分。先判事实和致命错误，再评四维；最终产物优先于“有没有按指定步骤思考”。

| 维度 | 0：不合格 | 1：基本达到 | 2：明显完整 |
|---|---|---|---|
| E 证据正确 | 核心事实、引用、计算或口径错 | 关键结论有可追溯依据，事实与假设区分 | 关键证据逐项对应，时效、冲突与来源局限交代充分 |
| C 任务覆盖 | 漏掉会改变结果的要求 | 交付明确要求，关键缺口已指出 | 覆盖必要边界和反例；不靠篇幅或多列无关框架加分 |
| J 判断质量 | 结论不由证据支持，忽略致命约束 | 推理与结论相符，说明主要假设 | 比较实质替代方案，说明敏感假设和何种新证据会推翻判断 |
| D 交付可用 | 用户仍需重做核心工作，或未产出 | 在约定格式/资源内完成，可进入下一步 | 可直接检查、复算或执行，关键责任/阈值明确 |

单次合格：全部题目关键断言通过、各维至少 1、合计至少 6/8，且无严重错误。四维部分分保留作诊断，但不把 8/8 等价为 SR。推理类评分必须附产物证据位置，不采信技能自述“完成度 98%”。

每题预先定义严重错误及为何会改变结论，例如伪造关键来源、把月收入当年收入、把 GMV 当平台收入、在资料不足时捏造确定结论、违反明确任务边界。不能事后因不喜欢答案而新增扣分规则。确认的严重错误使本次候选资格暂停；不能用其他题目的高分抵消。

成本、耗时、用户交互负担单列，预算上限进入题目合同。更慢更贵不能自动兑换高分；有质量/成本取舍则报告可比较条件。

### B. 个人化成长：来源与验证记录

| 状态 | 必须有的事实 | 视觉表达 |
|---|---|---|
| 通用 | 无可核对的个人适配记录；或尚未检查 | 无个人印记；区分“未记录”与“确认通用” |
| 已适配 | 用户明确偏好/反馈 → 具体内容或配置差异 → 适用范围可追溯 | 个性色、签名、纹样；不增加 foil 强度 |
| 经验证适配 | 固定同一模型/任务，通用版和个人版盲评；对新任务偏好符合度或返工量有改善，四维质量无实质退步 | 更完整的个人印记，附适配证据 |

使用次数、修改次数、篇幅、收藏、优先标记、作者名气都不能晋级。个人化必须能纠错和随用户偏好更新撤回；“迎合用户错误判断”是质量退步。通用版本可以是 SR，深度个人化版本也可以只有 C。若个人化版本确实通过同样能力门槛，可以为**该版本/该场景/该用户上下文**重新评级，但不能自动转移到通用版本。

## 4. 分级门槛：逐级满足，禁止只看百分比

以下数字是**待校准的 v0 产品门槛**，不是来源声称的科学常数。先用开发题检查任务难度和评分一致性，然后在首次正式运行前冻结；看过正式结果后改门槛必须升级规则、披露原因并使用新的锁定题集。

一题三次独立干净启动，三次均合格才记为“稳定通过一道”。**以下表中的稳定通过率 = 稳定通过题数 / n，绝不是 trial 通过率。** n 是不同业务问题数，不是调用次数；同一模板只换数字不算独立问题。全部失败和超时纳入分母，外部故障单列；作废题必须按预先规则对所有对照臂一起处理。记录首跑通过率和三跑全过率，发牌使用后者。

| 等级 | 最低表现门槛 | 必须补齐的证据 | 卡面 |
|---|---|---|---|
| U 未评级 | 缺少完整、匹配、锁定的评测 | 显示具体缺项；读过 SKILL.md 不算完成测试 | 素面 + 问号标识，不写 C |
| C 场景可用 | 至少 20 道锁定题，稳定通过率 ≥80% | 明确触发/依赖/输出边界；同环境无 Skill 基线；四类任务各至少 5 道、每类通过 ≥60%；无严重错误；人工抽查 ≥5 题覆盖全部题型 | 普通印刷、清晰 C 标识；无金边/镭射/粒子 |
| R 稳定增益 | 至少 40 道，稳定通过率 ≥85%，95% Wilson 下界 ≥70% | 四类各至少 10 道、每类通过 ≥80%；相对无 Skill 基线的配对增益 95% 区间下界 >0；人工盲审 ≥10 题；无严重错误 | 局部镭射，轻视差；文字不发光 |
| SR 对照验证 | 至少 80 道，稳定通过率 ≥90%，95% Wilson 下界 ≥80% | 四类各至少 20 道、每类通过 ≥85%；仍满足 R 的增益门槛；预先登记至少两个外部参考方案，与指定主对照的配对差值下界 ≥−5 个百分点；独立领域评审 ≥20 题，含失败和高风险边界；无严重错误 | 金色材质 + 全息层 + 稀疏粒子，详情才展开完整 3D |

四类是标准任务、复合任务、约束任务、缺证/冲突/诱导边界；它们是同一场景的难度分层，不要求一个市场规模 Skill 跨进写代码场景才能拿 SR。任务画像决定商业任务的行业/商业模式覆盖，各层达标防止平均分掩盖短板。

Wilson 区间只量化当前独立抽样任务通过率的抽样不确定性，不覆盖评审偏差、资料污染或样本代表性。分层抽样需同时展示各层结果；若任务相关，按原始业务问题聚类估计区间，不靠重复运行压窄区间。配对增益采用预注册的按业务问题聚类、分层 bootstrap（10,000 次、记录 seed）；记录所有对照，不把两个独立 Wilson 区间相减。

示例：16/20、34/40、72/80 的 95% Wilson 区间分别约为 58.4%–91.9%、70.9%–92.9%、81.5%–94.8%（已用 Python 复算）。它们分别达到 C/R/SR 的部分数字门槛，但**其他条件缺一项也不能晋级**。R 的高表现若没有证据证明 Skill 本身带来增益，只保留 C。SR 不意味着“行业最强”，只是达到本地任务标准并通过指定对照验证。

状态另外分清：`unrated` 无充分证据；`below_standard` 已测但未达 C；`current` 当前有效；`stale` 版本/环境/任务/规则变了；`suspended` 有确认的关键失败待修复。后三者保留历史结果，但 stale/suspended 不继续展示当前金光。新评测不达原等级则按本次有效证据降级，不能永远保留历史最高值。

## 5. Benchmark：先测最容易核验的商业场景

第一试点选现有 **“市场规模与竞争分析”中的市场空间测算任务**，不是一开始评所有商业判断。它同时有可复算数值、可核对口径、数据不足和策略判断，最容易校准什么叫好。当前 market-scale 只被描述为 TAM/SAM/CR1 专项，不能把一次测算成绩外推到全部竞品分析。

| 当前真实对象 | identity | 当前证据状态 |
|---|---|---|
| market-scale | `3b694b18-5f5e-4eaa-ac48-76d65445008d` × `scene-82935edd27b17fe4` | 只有内容与归属事实，U |
| business-coach | `ed2efaec-f1c1-4549-a047-a764736dd4e1` × `scene-36c2451fa91aad0e` | 商业项目推演，U；不从技能自述的段位体系借分 |
| demand-insight | `31dab295-2d0d-4c89-9236-e66e5ae799cb` × `scene-84484f3a7f5b4750` | 商业需求研究，U；不把作者标注的逆向提取完成度当能力证据 |

独立管理以下四份材料：

1. **任务合同**：用户要什么、可用资料、资源限制、什么会导致失败；不泄露参考答案。
2. **冻结证据包与参考断言**：来源正文/日期/hash、计算、已知未知、可接受替代推理。开放网络另测，不将“搜索到了什么”与推理能力混成一个不可复现分数。
3. **实验对照与轨迹**：B0 同模型无 Skill；B1 同预算的一般专业 checklist；S 候选 Skill；到 SR 再引入至少两份按公开发现规则选定、版本冻结的外部同任务方案。主对照在独立开发集上从 B1 和外部方案中选定表现最强者，再冻结进入保留集；披露检索范围、候选排除原因及主对照。不能测试完才挑最弱对手，也不以“搜索范围内较好”声称全球排名。
4. **评审记录**：算术和文件/引用事实用确定性检查；开放判断用锚定 rubric 和匿名随机顺序评审，LLM grader 先与人工校准。审题者、实现者、评审者角色和已看过答案的情况留痕。

OpenAI GDPval 使用真实职业任务及职业专家评估，可借鉴“按职业产物定义好坏”与盲评，不把它的模型结果迁移成我们的 Skill 分数。[GDPval 方法与局限](https://openai.com/index/gdpval/)

公开校准包位于 [benchmarks/skill-rating-v0/](benchmarks/skill-rating-v0/README.md)：12 道完整虚构商业资料题、明确断言与数值校验。**这些题及答案已可见，只能用于开发与校准，不是正式 holdout，也没有运行真实 Skill。** 初轮可先比较 B0/S 的少量输出来修 rubric，不因此发牌。随后收集至少 20 道不同的真实形态保留题，完成 C 门槛；R/SR 逐步扩展同一任务画像的独立保留样本。未运行的预算和调用量不得写成已有 evidence。

对预测性商业判断，先评决策过程是否利用当时证据、实验能否证伪、风险是否覆盖；等结果成熟再增加预先记录的预测概率和校准/Brier score。不能因为项目最终成功就认定当时建议正确，也不能用未来事实惩罚当时无法知道的判断。

## 6. 最小数据合同与兼容路径

初次接入新增独立 `card_master_skill_ratings_v1` 元数据，保持现有场景、Skill、组合、Agent 投放语义。先做存储/读取/校验和解释页，不建通用评测平台、排行榜或自动付费执行器。

| 字段组 | 必需内容 |
|---|---|
| identity | skillId、strict contentHash（含算法）、依赖版本清单、sceneId、taskProfileId/version、组合时完整成员 digest |
| environment | model/provider/version、harness/工具/权限指纹、时间/token/cost 预算、contextMode（通用/个人） |
| protocol | policyVersion、benchmarkId/version、tasksetHash、公开/开发/锁定用途、分层与采样规则、对照注册 |
| evidence | 按 task/trial 的输入引用、输出/工具记录和最终产物 hash、四维分、关键断言、失败、耗时成本、grader 及人工复核 |
| result | status、满足的最高 tier、n/通过数/各层结果、置信区间、配对对照差值、未满足门槛、评估日期、失效原因 |
| personal | 用户范围、偏好来源、版本差异、前后对照 evidence；与 ability result 分离 |

原始证据不可覆盖，结果从规则和证据派生；tier 不是可随意编辑的用户字段。所有 identity 在读取和展示前校验，摘要 hash 不能用 updatedAt 代替。规则或任务画像实质变化、Skill/依赖/模型/工具能力变化即 stale；场景单纯改名不失效，场景任务含义变化失效。网页资料的有效期由任务和来源声明，不能统一假定“90 天一定有效”。超出声明适用期则提示重测。

现有接入点已核对：

- `src/lib/skillScenes.ts`：归属；`src/lib/sceneCapabilities.ts`：能力与匹配；`src/components/SceneCapabilityGuide.tsx`：后续评级明细位置。
- `src-tauri/src/core/skill_scenes.rs`：已有 strict hash / stale 思路可沿用；新评级不得写入分类 reason/source。
- `scoreDeckSkill()`、临时 `quality`/coverage 是匹配启发式；已投放、优先项、归类成功、checkpoint 出现都不证明任务质量。
- `_evaluation/b0-r/` 测的是库事实理解与操作边界，其 C0 为未评分的定性基线；可复用证据管理习惯，不能复用为商业技能等级。

首次迁移所有既有卡片为未评级，保留归属、组合、优先标记、历史与 Skill 文件。记录缺项而不随机分配 rarity。组合 metadata 与评级 metadata 独立版本化，删除/改名不挪用他人的历史成绩。

## 7. holo-card 的皮肤合同

已从 RedSkill 安装 `holo-card@1.0.1`，其 SKILL.md 声明名是 **holo-card-studio**；供应的是 Blender + Three.js 制作与验证流程。安装不等于已生成或验收卡面。

| 样式 | 表面材质与动效上限 | 个人化允许变化 |
|---|---|---|
| U 未评级 | 普通静态表面 + “未评级”，不伪装成 C | 用户色、非稀有度印记 |
| 已测未达标 | 相同静态材质 + “待改进”，可查看失败证据 | 用户色、非稀有度印记 |
| stale / suspended | 相同静态材质；分别显示“需重测”或“评级暂停”，不写“未评级” | 保留历史个人印记 |
| C | 普通印刷，无 rainbow、金箔、高光粒子；纸张阴影可用 | 字体/纹样/签名 |
| R | 局部 spectrum/foil，轻微 tilt / parallax，无金框；只在交互中动 | 保持 R 动效上限的个人图案 |
| SR | 金边/金箔与全息叠层；允许稀疏粒子、主体/背景视差 | 保持能力标识清楚的个性艺术 |

源码发现：模板 `app.js` 的 edgeFragment 和 backFragment 在 `uFoil=0` 仍含 spectrum；`web_gold` 使用固定金色材质。因此普通卡不能仅设置 `foil:0`。后续必须在应用适配层分别控制 frontFoil / rainbowEdge / goldMaterial / lineEmission / stars / parallax / autoMotion，并让统一评级 resolver 给出全部材质开关。保留原 skill，不把产品规则硬改进供应商模板。

场景列表维持当前“目标 → 能力 → 完成判断”的阅读顺序，不恢复旧卡墙；列表采用静态卡面和小面积镭射，详情只激活一张 3D，避免每卡一套 WebGL。系统 reduced-motion 或用户关闭动效时变为静态，等级文字与纹样保留。失效状态可从历史页看旧卡面，但默认列表不持续金光。

真实用户看见：`R · 稳定增益`、`市场空间测算`、`34/40 · 评于日期`。展开后才展示基线、模型、区间、失败与未过门槛；不把工程参数散落在主卡面。示例分数只在明确标识“演示”的预览中使用。

## 8. 后续实施验收顺序
