# Scene Cards V1：按场景制卡

## 本轮原型目标

卡片从“一个 Skill 一张卡”改为“一个稳定工作场景一张卡”。场景卡让人一眼看到：要完成什么任务、由哪些能力组成、还缺什么、已经拿到了什么结果证据。底层 Skill 仍可被查询和复用，但不因数量多而批量视觉化。

本版把场景卡接入主程序Portal，验证稳定身份、组成内容与角色携带。尚未进行用户理解效果研究；不引入新的评级引擎、批量AI生成或工作流执行。

## 卡片行为

| 情况 | 处理 |
| --- | --- |
| 识别到已有稳定场景 | 使用既有 `sceneId`，更新该卡的材料、缺口或结果证据。 |
| 同一 Skill 服务两个不同任务目标 | 两张场景卡可引用同一 Skill。 |
| 新资料仍服务当前任务目标 | 加入当前场景卡，不新建卡。 |
| 新资料有独立目标与成功标准 | 新建一个稳定 `sceneId` 的场景卡。 |
| 归类不确定 | 保持待归类，不造“其他”场景卡。 |

## 卡面与审核

卡面说场景目的；背面呈现能力组成、缺口与结果证据。Skill 摘要的来源核验沿用 forge 的 `card-copy` 标准，但摘要仅为材料。

场景评级只审“完成该任务的整体方法和结果证据”。成员数、成员平均等级和最高等级均不构成总评级。没有审核证据就显示“未审”。凡、灵、天、圣保留为独立视觉语义：完整功能、内部路径、条件响应、装备与场景领域的关系；它们不衡量任何个人或 Agent 的能力。圣领域允许随着场景迭代演进，不能由美术或成员替换自动升级。

## holo-card-studio 联动

每张场景卡可以输出一份 `artDirection` 交给 holo-card-studio：场景装备、领域（适用时）、两者关系和风格配方。默认只生成场景主视觉；成员 Skill 不需要逐一出图。只有明确请求时，才继续做分层、动效或 3D 交付。

## 无证据限制

来源未核实、方法摘要未成立或结果没有可复核记录时，卡面必须保留待整理、缺口或证据不足状态。不能用成员 Skill 的名气、等级、数量或漂亮的视觉补齐。底层Skill原文仍可逐项查看，场景用途/结果的深度讲解需要后续按场景整理。

## 当前主程序实现

- 从正式 `get_skill_scene_overview` 读取场景和归属，结合真实受管库投影；一稳定scene ID一张卡。失配或缺失成员不生成幽灵卡。读取失败保留整份旧快照。
- 卡正面展示场景名与组成数，背面保留整个场景描述及组成概要；详情以文字列表展开成员原文，未整理的场景说明如实留空提示。不会在入场时对几百个Skill读全文或制图。
- 目前已有场景成员是Skill；资料/检查点/结果证据属于生成规范的可用输入，本次没有新增通用内容存储、自动评价或执行编排。
- 场景卡图案暂用共享轻量图形，未把它们标成定制神器。后续精作主视觉以场景为单位，既有holo动效/3D合同保持。
- 场景手册的「整理此场景」回到工作台该场景，复用已有名称、说明和Skill归属编辑；不会直接修改归属。
- v4场景配装与v3单Skill配装分开。身份和旧选择保留，场景选择从空开始；未知场景引用仍保留。可解析但损坏的v4不会被启动时的默认值覆盖。携带选择可投影为去重成员集供未来连接使用，当前不等于真实安装/任务调用。
- 已安装 `skill-card-forge` 和 `skill-grade-review` 已同步场景单位，旧单Skill文案/评级记录保留为独立历史材料，不继承为场景评级。
