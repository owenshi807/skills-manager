# Skill 卡片能力讲解 v0.1

日期：2026-09-09。用户要求卡背简短地解释 Skill 价值，游戏内用讲解本领的方式组织复杂信息，并形成可持续迭代的标准。

## 采用的标准

正面是清楚的名称与一句价值；背面讲清用途、产物、独特机制以及会影响选择的条件。点「本领手册」后先看用法概览、输入与产物，再按需展开原始说明、来源与维护信息。卡背不显示源版本、指纹、部署计数和工程警示墙。

参考 [两个官方游戏表达案例](research/card-copy-references.md) 的动作/对象/结果与关键条件表达，形成 [文案标准、可执行生成 prompt、JSON Schema、审核 rubric](../../skills/skill-card-forge/references/card-copy.md)。此规范已经接入既有 skill-card-forge 并同步其已安装版本，美术与 holo-card-studio 的原有分层/3D合同保留。

## 三个真实范例

| 中文展示名 | 原始 Skill | 一句话价值 | 不可删掉的区别 |
|---|---|---|---|
| 资料入库把关 | knowledge-audit | 在资料入库前先过一遍审核，判断该继续收录还是停下。 | 面向 Obsidian Wiki；需规则与完整原文；通过后继续收录。 |
| 方案追问 | grill-me | 一问一答拆清关键选择，弄明白方案为什么这样做。 | 一次一个问题，给建议答案，需要使用者参与。 |
| 商业项目推演 | business-coach | 从需求、赚钱到增长，找出最该先验证的项目风险。 | 按模式产出关键假设、画布或验证路径；假设仍需实测。 |

knowledge-audit 是路由入口。人工读过当日本机正式 adapter，但产品只核验卡库入口正文，未实现跨库规则/依赖运行时核验。因此它的讲解限定入口能支持的收录前审核，不承诺目标知识库已可执行。知识准入 A/B/C/F、教练诊断层级不转化为 Skill 品阶或个人能力。

## 实现边界

- 首批为三类 Skill 的人工精简文案；按名称筛选候选后，使用完整正文 SHA-256 精确匹配，名称和 Manager 旧指纹都不能独自授权文案复用。变化后退回原说明/待整理，不伪造新版本效果。中文别名也进入搜索。
- 其余卡片保留短而完整的原始说明并标记「原说明摘录 · 待整理」；过长/无完整句的内容显示能力说明待整理，详情仍保留作者原说明。没有声称全库完成蒸馏。
- 新的 AI JSON 标准是后续编辑/审核合同，目前前端仅消费审校后的简化字段，不会自动执行 prompt 或把模型输出直接授予评级。
- 原文通过已有原生 read_skill_publish_document 命令固定读取该 Skill 的 SKILL.md，单次最多128KiB，长文会明确提示未读完；身份/结构不一致则拒绝。纯文本渲染，不解释其中 HTML、脚本或指令。
- 普通卡原文按展开读取；三类范例进入卡库时各自读取核对一次，失败不丢整库。关闭或更换手册后，迟到返回不得改写新手册。
- 技能卡/角色/仓库/品阶仍是各自独立的产品事实；携带仅本机选择，不写远端装备、运行任务或声称人物掌握能力。

## 验证

文案11项、库存/文档端口6项单测；文案UI6组（正文变更、长文提示、HTML惰性、失败重试、关闭竞态、390px条件无裁切）；角色8组；Portal9组（含20次释放、短窗、90–120%缩放）；官方develop-web-game动作客户端两轮。均通过，截图人工查看。独立只读检查发现的父容器刷新所致滚动位置与Esc顺序问题已修复，并由最终文案UI回归覆盖。

原生App验证结果与最终摘要见 [最终验收目录](verification/card-copy-v1/)。仅保留代表截图和精简报告，临时重复截图和安装回退副本已在验证后清理。

## 后续迭代入口

继续按场景逐批整理实际常用卡片；每批优先验证使用者能否从卡背说清「什么时候选、会得到什么、需要什么条件」。新来源/规则变化时重新审校，未知内容诚实回退。表达问题给一条可操作的改写建议，不改变该 Skill 已有品阶。
