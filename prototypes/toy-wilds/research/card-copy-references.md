# Skill 卡背表达：两个官方游戏范例

核查日期：2026-09-09。以下只借鉴官方说明的组织方式，不借用游戏数值、平衡设定或效果作为 AI Skill 的能力证据。未下载游戏、安装依赖或修改生产代码。

## 范例一：Overwatch 的能力短句与机制补充

官方来源：[Blizzard 对 Overwatch: Classic 原版能力的说明](https://news.blizzard.com/en-us/article/24146047/a-blast-to-the-past-begins-with-overwatch-classic)，定位 Genji 的 Swift Strike 与各英雄的补充说明。该页面明确介绍 Classic 的 1.0 玩法，应作为表达范例，不作为当前常规模式的数值资料。

短引文（12 个英文词）：

> Rapidly dash forward and inflict damage on enemies. Eliminations reset the cooldown

观察到的信息层次：

| 层次 | 页面怎样表达 | 可借鉴的作用 |
| --- | --- | --- |
| 能力名 | 每项能力先给名称，再配一条短说明 | 名称负责辨识，不独自承担解释 |
| 基础效果 | 冲刺的方向、伤害的对象写在同一句 | 读者立即知道做什么、作用于谁 |
| 关键机制 | 紧接着说明击杀会重置冷却 | 改变用法的触发条件保留在短说明中 |
| 补充解释 | 各英雄另有版本差异与细节段落 | 说明复杂差异，不把所有背景塞进能力短句 |

该页也直接写出有些能力不能射击、不能提前取消等限制。值得借鉴的是：简短不等于只留好处；会改变选择的限制与关键触发应有明确位置。以上分层是对官方页面的分析，不是 Blizzard 发布的写作规范。

## 范例二：Hearthstone 的关键词与完整规则解释

官方来源：[Blizzard 的 TITANS 上线说明](https://hearthstone.blizzard.com/en-us/news/23973123/titans-is-now-live/)，发布日期 2023-08-01，定位 Forge 关键词段落。

短引文（17 个英文词）：

> Cards with the Forge keyword can be dragged over to your deck and upgraded for 2 mana.

观察到的信息层次：

| 层次 | 页面怎样表达 | 可借鉴的作用 |
| --- | --- | --- |
| 统一机制名 | 用 Forge 标识一类可执行机制 | 重复规则可以有统一的简短名称 |
| 适用对象 | 明确限定为带该关键词的卡 | 读者知道规则适用于什么 |
| 操作、成本与结果 | 拖到牌库、花费法力、升级卡牌 | 关键词展开后仍是一条能理解的完整规则 |
| 更深资料 | 页面另链补丁说明与官方卡牌库 | 详细资料有明确入口，读者无需从短文推测全部细节 |

这个来源验证的是关键词的官方规则解释与资料层次；本次没有操作游戏客户端，因此不将其说成已实测的悬停提示交互。AI Skill 可提供点击展开的关键词解释，但这是本产品的设计建议。

## 对 AI Skill 卡背的建议

采用“效果短文 → 关键机制与条件 → 完整档案”的顺序。卡背让用户判断这张卡是否适合当前任务；完整档案承接原文、例子和可追溯依据。

1. **效果先用普通动词写清。** 交代输入或对象、执行的核心动作，以及可检查的产物。任务收益不能替代实际产物：只写“提升质量”“深度赋能”无法判断它会做什么。
2. **关键机制不能被摘要抹掉。** 多阶段确认、按条件分支、交叉质询、验证后修订等，如果决定这个 Skill 的独特用法，就保留在卡背。压缩重复措辞，不把复杂工作流改写成一次万能处理；放不下时增加可展开正文。
3. **条件与副作用必须在决策前可见。** 来源要求的输入、联网或工具前提，以及文件修改、发送、发布等行为，应写在卡背相邻的条件行。完整步骤可放档案，但不能让用户翻完档案才发现会发生关键写入。
4. **关键词只用于真实、重复的规则。** 例如“需联网”或“先确认再执行”只有原 Skill 确实如此才使用；点击可见白话解释，手机也能访问。少量有效关键词已经足够，不用一屏陌生缩写代替说明。
5. **不编造游戏数值。** 不凭空生成成功率、效率倍率、耗时、冷却或能力分数。真实约束可以保留原数值；统计指标只有具备版本、样本和验证方法时才进入证据区。未知就标为未验证，不用一个看似精确的数字补空。
6. **效果说明与执行状态分开。** 卡背描述该方法能做的事；“本地已携带”只说明本机选择，不意味着远端 Agent 已装配、已经调用或已产生效果。本轮没有真实 Agent 执行，文案不能暗示装备即自动运行。

可用于编辑时检查的模板（占位结构，不代表任何已核验 Skill）：

```text
把〈输入或对象〉经由〈核心动作〉整理成〈可检查的产物〉。
〈关键阶段或触发条件〉，随后〈决定性的后续动作〉。
使用条件：〈必要输入、工具前提与关键副作用〉。
完整档案：原始说明、详细步骤、例子、来源版本与验证证据。
```

这个模板是编辑检查工具，不要求把四个字段机械贴满每张卡。若某项不存在就不凑；若效果不能从 Skill 原文证实，应先保留原说明或标为待补充，不能用游戏语气掩盖未知。

验收判断：用户应能从卡背回答“它处理什么、怎样处理、交付什么、有哪些会改变选择的条件”；进入完整档案后，仍能找到摘要中每条承诺的原文依据。删除专有词以后意思仍然成立，才适合放在游戏卡背上。
